# 白璎跑团系统

2026-11-11 实现；2026-11-12补齐 [AI主持与自然语言接续](trpg-ai-host.md)。基于 CoC 7；这是可保存、可审计的主持辅助系统。数字由程序裁定，模型负责公开描写与意图澄清。新模组的场景、隐藏事实及特殊裁定须由KP审查后采用；不会让模型读完整秘密再自由编结局。

## 开始与继续

控制台侧栏“跑团”可查看状态、角色、额度、战报和场景关系图。默认只显示公开视图；勾选“以本团KP身份管理”才显示秘密。控制台操作只在本机显示，不自动给QQ发消息。

QQ常用命令：

```text
/团 帮助
/团 创建 团名
/团 成员 QQ号 player
/团 状态
/团 角色
/团 检定列表
/团 投骰 检定编号
/团 应对 检定编号 闪避
/团 授权 开
/团 暂停
/团 续团
/团 战报
/团 导出
/团 额度
```

运维主人负责建团；本团KP负责登记成员和裁定，其他团KP没有跨群权限。每个玩家绑定独立角色卡，旁观者不能代替玩家行动。开团后登记玩家的自然语言进入行动通道；`团外：内容`继续日常聊天。旁观者明确叫她时仍可日常交流，不把闲聊当团行动。

确定匹配的已配置行动直接执行；有歧义时最多一次短模型调用，只建议已有行动编号，由玩家确认。不认识的行动交由KP补充裁定。没有批准的效果不会因模型说“成功”而进入存档。

角色卡可通过控制台录入属性、技能、资源、物品与状态。改卡需暂停并填写理由。未知技能数值会报错，不能由模型猜；已知基础技能使用程序明确列出的基础值。

## 检定与战斗

KP在控制台“宣告正式检定”填写玩家固定人物ID、技能、目标和失败风险。程序先展示完整技能值、难度目标和奖惩；低于20额外警告，确认前不掷骰。代骰授权不允许省略风险宣告。

高级操作参数也支持 `/团 操作 JSON`，例如：

```text
/团 检定 {"actor":"玩家固定ID","kind":"skill","skill":"锁匠","reason":"尝试开启栅栏门","risk":"工具可能折断","difficulty":"常规","failure_text":"门未打开"}
/团 检定 {"actor":"玩家固定ID","kind":"sanity","reason":"首次目击恐怖景象","risk":"失败损失1d3理智","success_loss":"0","failure_loss":"1d3"}
```

正式检定与团状态在同一个SQLite事务保存。真实随机数沿用安全骰子解析器；出目、请求、规则快照不可覆盖。QQ消息ID、原生工具调用ID与控制台请求ID去重；重试或查询原请求不重投、不重复扣点。自由骰 `.r/.ra` 与正式团骰账本独立。

支持：

- 常规/困难/极难、百分比奖励/惩罚、成功等级与失败边界。
- SAN损失、大失败最大损失、单次损失5及以上的INT检查与疯狂提醒；叙事日累计达到起始SAN五分之一的提醒。疯狂症状和持续时间由KP裁定，不偷偷补演。
- 普通对抗；近战闪避同级防守方胜、反击同级进攻方胜；双方失败不命中。普通对抗技能也相同的平局需KP决定是否另做决胜检定。
- DEX轮次、近战人数优势、进攻与反击伤害、极难伤害、贯穿、HP、重伤、昏迷、濒死CON检查、死亡；单发枪械扣弹药。
- 急救+1、医学1d3；同一伤口不能重复刷同类治疗。医学需确认装备并推进一小时；急救时限等现场条件由KP核验。治疗达到半血或极难成功可解除重伤。
- 失败普通技能的一次孤注，须先宣告更严重风险；禁止将战斗、理智、幸运或已经孤注的骰重投为普通孤注。
- 显式房规 `luck_spending`（默认关闭）。启用后可花幸运的失败会先锁定原骰，等待 `/团 接受结果 编号` 或 `/团 花幸运 编号 点数`，再提交相应后果；不能制造大成功，不能倒改已接受后果。
- 成长标记与成长检定、物品、MP/幸运、已公开线索、场景标志及已确认剧情耗时。

扑倒掩蔽、多发枪械、自动武器、追逐、完整自然恢复、魔法等复杂或可选规则尚不自动结算。须先由KP依据来源宣告裁定，再用明确的难度、奖惩和单次请求处理；系统会拒绝把枪械当近战闪避/反击。不把本版说成完整自动化的七版规则引擎。

“战斗”操作需参战角色编号；“结束战斗”保留伤势和弹药。“状态裁定”用角色编号及add/remove列表解除或添加已核定状态，必须有reason。“裁定”记录name/text/source/public，保留适配出处，不擅自改写算法。

## 场景与本地模组审核

KP可分步录入场景和事实，或在高级操作中使用“模组草案”，参数为 `{"draft":{...}}`。草案只在本机保存；检查完整状态中的 `module_draft` 后执行“采纳模组”。本地草案不会自动外发；另行明确授权的AI主持可在独立上下文读取本团指定版本，见AI主持说明。

```json
{
  "draft": {
    "scenes": [{
      "id": "hall", "title": "门厅", "public": "雨水顺着窗沿淌下。",
      "private": "KP使用的提示",
      "actions": [{
        "id": "desk", "title": "查看桌面", "aliases": ["查看桌面", "看看桌子"],
        "requires": {"desk_checked": false},
        "success": [{"type":"reveal","name":"note"},{"type":"flag","name":"desk_checked","value":true}],
        "success_text": "桌面上有一张纸条。"
      }]
    }],
    "facts": [{"id":"note","text":"已批准可揭示的纸条内容","source":"文件SHA / PDF物理页3；待校勘"}],
    "notes": "首次使用前请通过场景标志设desk_checked=false，或移除requires。"
  }
}
```

`skill`存在时先建立待确认检定；否则直接执行已批准效果。效果支持item、flag、scene、reveal、minutes、resource（仅MP/LUCK），每次最多12项。HP/SAN不能通过通用效果绕过伤害/理智规则。场景图从实际转场引用生成，房间编号不自动变成线性路线。已公开信息在回滚时仍保留可见性。

## 资料和记忆

资料库按团隔离，PDF/MD/TXT按页或段建索引；检索最多返回3个相关片段，附来源、文件SHA、页/段编号及未校勘标记。带PDF页标题的MD保留原物理页号，印刷页未知则为空。无文字层且无已完成识别结果时提示人工授权识别，避免自动扫描整本书消耗额度。

可见性为public、party、character、kp。KP全文只能在有权限的专用私聊或本机控制台读取；普通聊天模型的团务工具不能请求private全文。公开叙事模型只接收当前公开场景、已揭示事实、必要角色摘要和少量公开事件。

受保护来源登记到 `data/run/trpg-protected.json`。普通读/发文件、历史、长期事实/情景检索、共享近期经历会过滤受保护来源；原文件、同指纹副本、ZIP内副本、已登记页图/OCR缓存也受检查。通用电脑助手禁止读取团库、备份和已登记秘密路径；历史KP任务不允许从普通聊天恢复。原始资料与日志保留，不修改为“从未公开”；既往泄露无法撤回，Windows管理员也不受此应用权限约束。

日常群聊与私聊记忆继续共享。公开团状态可由同一成员在私聊显式指定campaign查询；私聊提示会列出参与过的团，暂停与日切后仍可找到。角色伤势等带fiction标记，不抽为现实人物事实。睡眠和stop继续整理日常记忆；团状态每次操作实时提交，独立于聊天线程压缩和轮换，现实离线不推进叙事时间。

## 额度控制与实际验证

查询、角色、骰子、确定行动、物品、存档与检索由本地程序执行。2026-11-12增加白璎作为统一交互入口：工具报告交给她解释、追问或整理，通常需要一次短调用；忙碌或预算不足时仍可返回自然语言摘要。未匹配的动作支持主持问答与受限普通检定提案，反馈至多修正一次；同消息回执和成功结果复用，交互判断的连接失败冷却后可重新发送，不永久缓存为失败。公开通道使用独立线程，默认8次调用后从权威状态重建，限制累计历史；不会更换日常持久线程策略。

默认限额：全部团合计每日120次模型调用、600000提交输入字符、单轮7000字符、描写500字、最近4项公开事件；任一订阅窗口已用85%时暂停跑团AI，默认不启用付费兜底。程序功能继续可用。以上均可在控制台“设置→跑团”调整，重启生效。按本机日期计算；失败调用也计数，计量保留实际输入/输出/缓存token，后端未提供则显示未知。单轮字符上限不等于持久线程总输入token上限。

日常聊天的人格与工具说明按版本增量发送；实时人物、事实、时间及任务状态仍每轮刷新。后台任务默认只带简短状态，避免反复发送旧要求和结果。

早期程序直出模式的本地假模型验收见 [trpg-quota-benchmark.json](trpg-quota-benchmark.json)：20次状态查询0次模型调用；8次需要描写的行动加8次同消息重试共8次调用；样例最大868个提交字符。这是历史基线，不代表现行白璎统一交互模式的端到端调用量。群任务状态提示由2388缩至134字符。样例不代表完整剧情长度，也没有用真实订阅压测。订阅额度并非简单字符/token线性换算，不承诺固定节省百分比；缓存是否命中以实际计量为准。

## 本群恢复与运维

迁移工具 `scripts/ops/migrate-trpg-20261111.py --root E:\04AI\Agent` 默认预览；加 `--apply`才创建暂停草案。以11月11日15:54存档为基准：HP5、SAN64，停在牢房外斧击落空之后。保留全部原文件、原骰和原卡，不追加NPC行动。HP5仍标重伤与标准规则的差异、未确定DEX轮次等列在KP可见 `state.migration.uncertainties`。

核对后由本团KP执行 `/团 确认恢复`，仍保持暂停，再按需 `/团 续团`。2026-11-12已安装来源锁定的旧团接续包：34场景、21事实、5个NPC实例。玩家在原群说“继续跑团”，核对摘要后说“确认继续”；后续使用自然语言行动。详见 [AI主持说明](trpg-ai-host.md)。

数据库 `data/trpg/state.sqlite` schema1；每次更新有状态版本、前态快照及事件。回滚需暂停、给出版本和理由；保留原骰和已揭示线索。outbox先提交、后发送；发送结果未知不自动重发，QQ重启将sending转为unknown，可用“回执”核对。备份位于data/backups，源代码部署前校验基线指纹。若回退代码，保留团库与保护清单；恢复旧代码会失去资料过滤能力，不能直接开放旧文件工具。

## 规则与技术来源

公式与裁定依据 Chaosium 官方规则摘要核验：[检定与对抗](https://cthulhuwiki.chaosium.com/rules/game-system.html)、[战斗](https://cthulhuwiki.chaosium.com/rules/combat.html)、[理智](https://cthulhuwiki.chaosium.com/rules/sanity.html)、[伤势与治疗](https://cthulhuwiki.chaosium.com/rules/hit-points-wounds-and-healing.html)、[成长](https://cthulhuwiki.chaosium.com/rules/rewards-of-success.html)。本群中文规则文本有缺章及OCR疑点，未补造为官方全文；复杂细节仍以已锁定规则版本和KP明确裁定为准。

线程与用量采用 [Codex app-server](https://learn.chatgpt.com/docs/app-server) 接口；稳定前缀有利于缓存，但复用线程不保证缓存命中，参考 [OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)。
