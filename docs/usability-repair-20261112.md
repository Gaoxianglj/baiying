# 白璎群聊、文件与新团筹备修复

本次在正式白璎关闭状态下修复。部署后仍保持关闭，正式群未自动恢复，真实团档未用于模型演练。私人测试群1127596568已加入白名单；测试时只启用该群，独立数据目录不混入正式记忆或团档。

## 文件能找到、能继续读取

- 群上传通知静默保存；消息中的文件与通知中的文件都保留文件ID与busid。NapCat `get_file`使用`file`参数，失败后继续尝试当前群的文件下载URL。
- 当前聊天可读文件目录随请求提供。文件名可以递归定位子目录中的唯一文件，历史日期目录继续可读；同名多份时列候选。先搜索本地，再按需查询当前白名单群的云端文件，不要求用户反复重传已存在文件。
- XLSX可提取工作表名、单元格位置、文本/数值和公式缓存。无缓存公式标注未计算；不执行公式、宏和外部链接，超大表格有读取上限。PDF沿用已有文字提取与按页识别功能。
- 每个聊天仍有独立文件夹。文件清单、搜索和预览继续执行原有权限、密钥过滤与KP资料保护，云端工具没有任意群号或URL参数。
- 模型尚未尝试工具就回复“看不到、重传、贴正文”时，内部要求其先查找并读取一次，再向用户发送最终答复。

协议参数依据：[NapCat OneBot API](https://napneko.github.io/onebot/api)、[官方文件接口示例](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/action/example/FileActionsExamples.ts)。

## 接话与语气

- 点名、@白璎、回复白璎可直接邀请。明确点名白璎的请求可以同时@另一个玩家作为操作对象；单独@别人或回复别人不自动接入。
- 活跃期只接原对话参与者的明确延续；其他成员须明确邀请加入。自动延续默认最多两轮，重新点名后重置，不再把整群所有人持续升级为对话伙伴。
- 日常闲聊、简短附和及模型/后台设置讨论不自动触发跑团主持。动作、已登记技能/物品和控制请求仍可自然表达。意图识别有边界，含糊句可点名白璎说明目标。
- 公共与私聊人格提示统一要求自然、直接、符合白璎人设；减少习惯性“X不等于Y”、自我辩护和反复道歉。正常纠错与必要澄清保留。此项由提示约束，仍需观察后续真实对话效果。

## 白璎操作筹备系统

- 新增内部【筹备团】工具，提供准备、绑定角色、关联资料、检查。可复用草案、核对八属性与技能、解析QQ固定身份、关联规则/模板/受保护模组、设置已有公开开场并检查是否可启动。
- “我/self/当前用户”等指向真实请求者；同聊天唯一团名可以定位存档。常见参数差异内部修正，后台任务现有工具清单补齐团务能力，任务结果必须对应真实系统状态。
- 已有角色不同则拒绝覆盖，普通旁观者不能改团或授予主持权限；不因新团任务恢复旧团、不伪造角色数据或隐藏规则。
- 主人主持者可启用公开主持，处理已登记公开信息。模组关联与私有模型授权继续分开，隐藏资料仍用原来的指定来源授权流程。
