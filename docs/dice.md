# 真实骰子与 CoC 七版检定

实施：2026-11-11。依据：群内当天 11:10 白璎给出的骰子约定（事件 `7acf630081b14c4880c9078698ba246d`），
本轮完成基础投骰、百分比检定、奖励/惩罚骰和记录。理智损失、角色卡与剧情状态尚未自动化。

## 使用

无需 @、无需模型生成的直接指令（仅接入的群与私聊）：

| 指令 | 行为 |
| --- | --- |
| `.r 2d6+6`、`/掷骰 2d6+6`、`/r 2d6+6` | 两个六面骰加6，逐颗显示和汇总 |
| `.r`、`/掷骰` | 默认 d100，出目1～100 |
| `.r (d6+2)-1` | 加减、括号、整数，省略骰数即1颗 |
| `/检定 60｜常规｜幸运`、`.ra 60 幸运` | 完整技能值60，常规难度 |
| `/检定 60｜困难｜奖1｜侦查` | 技能60、目标30，一颗奖励骰 |
| `.ra 60 极难 奖2 罚1 侦查` | 奖惩先抵消，最后留一颗奖励骰 |
| `/骰记录`、`/骰记录 10` | 当前聊天最近5条或指定1～10条记录 |
| `/骰记录 记录编号` | 取回当前聊天这一条的完整结果 |
| `/骰子帮助` | 显示用法 |

指令受原有 QQ 每分钟回复上限控制，限流时不抽样。无效表达式不掷骰、不写结果。
天然语言让白璎代投时，她可以使用 `【掷骰：表达式】`、`【检定：技能值｜难度｜奖惩｜说明】`、
`【骰记录：数量或编号】`；Codex 同时可使用对应的原生结构化工具，不需要开启命令沙箱。
直接指令的原始输入与结果同步进入聊天事件，之后白璎能据此继续判定；本次上线不会自动结算先前悬而未决的幸运检定。

## 判定规则

- 常规目标 S；困难 floor(S/2)；极难 floor(S/5)。同时显示实际成功等级和是否达到要求。
- 大成功：1。大失败：S<50 时96～100，S≥50 时仅100。使用完整S，不能把困难目标当技能值。
- 优先判大成功/大失败，再依次极难、困难、常规、失败；成功等级与所需难度分别计算。
- 百分比共用一个0～9的个位，额外抽十位；每项组合为1～100，00+0按100处理后再比较。
  奖励取最小，惩罚取最大。一类奖惩最多输入20颗用于抵消，净额最多2颗，超出报错，不静默截断。
- 技能值1～999；不提供修改大成功/大失败阈值的房规开关。需要房规时另立版本，不改既有记录。
- 不自动重投、不扣SAN、不改卡、不凭大成功或大失败替KP决定剧情、伤害和疯狂后果。

基础语法：`NdM`、整数、`+`、`-`、括号、一元正负号；不支持乘除、函数或代码。
表达式最多160字符、64语法节点、12层嵌套、合计100颗骰子，面数1～1,000,000；
整数及可能的中间/最终结果绝对值不超过1,000,000,000。全部解析和预算检查通过后才抽样，完全不使用 eval。

## 随机与记录

使用操作系统随机源 `secrets.randbelow`；无法由聊天输入指定种子、点数或覆盖已发布结果。
记录位于项目 E 盘 `data/run/dice.sqlite`（沿用程序状态目录访问限制）。每条有编号、UTC时间、
body/channel、操作者、请求及规则版本、逐颗出目/十位候选、总和、目标、等级和难度结论。
先提交数据库，提交失败不公布出目。数据库是本机审计记录，不承诺能防止持有电脑权限的人篡改。

相同聊天、操作者与 QQ 消息编号，或者原生工具 call_id 的重复投递，会返回原已落盘结果；
同一编号换参数则拒绝执行。用户新发指令有新编号，属于新投骰，保留另一条记录，不覆盖旧结果。
未带固定编号的文本技能调用每次单独记账；模型提示明确禁止未经新授权重投刷点。
本轮不提供待定检定锁定，因此模型的判词仍需核对记录，后续跑团裁定须引入明确检定请求与状态提交。
群里可查本群骰子记录，私聊只能查当前私聊；共享长期记忆不会赋予跨聊天查询骰子数据库的权限。

控制台：`技能·骰子 → 真实骰子与CoC检定`，对应 `skills.dice.enabled`，默认开启；
关闭并重启后直接指令与模型骰子技能都停用。无需新增依赖、系统环境配置或修改个人 Codex 配置。

验证使用确定的随机输入核对所有边界、共用个位、00+0、抵消、持久恢复与并发重复请求；
另用假的QQ验证直接发送、权限、限流、事件同步、无模型调用和发送失败重试，没有向真实群发测试消息。
