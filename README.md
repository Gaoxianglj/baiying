# 白璎：长期记忆 AI 伙伴

一个记忆存在本地的 AI 伙伴。核心是长期记忆；QQ 聊天和《我的世界》是两个验收用的“身体”。模型可以随时更换，记忆和人格不会丢。

私有仓库。公开后不允许商用。

## 开发

需要 [uv](https://docs.astral.sh/uv/) 和 Python 3.13。

```bash
uv sync
uv run companion config    # 查看生效配置（密钥打码）
uv run companion init      # 创建记忆文件夹 data/memory/
uv run companion chat --as <你的id>   # 命令行聊天
uv run companion qq        # 连接 NapCat，在 QQ 上运行
uv run companion web       # 本机控制台：状态、今天、设置、种子、人物与记忆、日记
uv run companion sleep     # 手动做一次“睡眠”
uv run python scripts/replay.py   # 用现在的提示词重放真实聊天，和当时的回复并排对比
uv run pytest
uv run ruff check .
```

## 一键启停（后台运行）

- `start.bat`：依次启动 Ollama → NapCat（用 `.env` 的 `QQ_BOT_ACCOUNT` 快速登录；需要扫码时自动弹出二维码图片，扫完继续）→ 主程序 → 控制台，全部在后台运行，关掉窗口也不会停；最后打开控制台（地址固定，可收藏）
- `stop.bat`：主程序先整理完这次的对话再退出；然后停控制台、NapCat（只停 NapCat 目录里的 QQ，不动你平时用的 QQ）、Ollama。保留某项：`stop.bat -KeepOllama` / `-KeepNapCat`
- `status.bat`：查看各服务是否在运行
- 主程序和控制台崩溃后 5 秒自动重启，且同一时间只允许运行一个实例
- 日志在 `data/logs/`（`qq-日期.log`、`web-日期.log`），运行状态在 `data/run/`
- `.env` 里可设 `NAPCAT_DIR`（NapCat 目录）和 `CONSOLE_PORT`（控制台端口，默认 8765）

## 聊天上下文与睡眠整理

默认启用 `models.subscription.persistent_chats = true`（控制台“聊天保持上下文”）。
普通聊天按频道保存 Codex 线程，已有消息按事件编号去重；线程自动压缩由 Codex 处理。
每轮仍刷新人格、当前人物、检索记忆、任务状态和技能权限。记忆抽取、反思、看图等辅助调用
保持独立临时会话；屏幕和剪贴板工具结果也只交给临时会话，保留只用于当前轮的规则。

私聊与群聊仍共享原有长期记忆，并能检索近 24 小时其他聊天的相关普通消息（最多 6 条，
每条最多 500 字），不必等待空闲抽取。它们是标注来源的回忆资料，文件权限和原始记录工具
权限仍分别检查。持久线程恢复时还会同步当前聊天近 24 小时尚未投递的事件，补回兜底模型
期间或她没有发言时的对话；兜底 API 的原有最近消息窗口和长期记忆提示词继续保留。

原始事件即时保存，原有空闲 30 分钟后的会话整理仍运行。每日睡眠先强制整理包括仍活跃的
会话，按事件分批提交游标；成功后轮换聊天线程，再继续使用人物档案、事实、日记与检索记忆。
抽取失败不轮换、不标记睡眠完成，维护循环会重试。主动 `stop.bat` 或 Ctrl+C 正常退出时，
先整理再轮换；崩溃后优先恢复原线程，上一轮生成状态不确定或历史缺失时从现有事件重建，
不会假称恢复了中断命令。后台任务线程不参与这次聊天轮换。

线程索引和投递编号在 `data/run/chat-sessions.sqlite`，不含消息正文；原始消息、抽取游标、
人物和长期记忆仍在原位置。Codex 原生 rollout 沿用现有登录目录（本机是
`C:/Users/Lingji/.codex/sessions/`）；这是保留既有登录和个人 Codex 配置的存储例外，
本次未迁移或修改该目录配置。线程索引、测试数据及新应用数据均在项目 E 盘。
日切和关闭持久聊天不删除原生 rollout；“忘记”会保留原有记忆/出处删除行为，并使本项目
旧线程全部失效，不再把其上下文或压缩摘要用于后续聊天。原生历史的永久清理未启用，
不能把线程失效理解为已从 Codex 历史物理删除。关闭“聊天保持上下文”并重启可恢复临时线程。

## 她能碰哪些东西

规则由程序保证（`src/companion/skills/access.py`、`history.py`），不靠她自觉。

| | 群聊、别人的私聊 | 主人私聊 |
| --- | --- | --- |
| 聊天记录和里面的图 | 当前聊天；群里还能翻别的群（`skills.history.scope`） | 全部 |
| 这个聊天的文件夹 `data/workspace/chats/聊天/` | 能存新文件、能读、能发 | 同左 |
| 这个聊天收到的文件 | 能读、能发 | 同左 |
| 别的聊天的文件夹和收到的文件 | 不行 | 能读、能发 |
| 本机其他文件 | 不行（`skills.files.group_read_paths` 里的文件夹群聊只读） | 能读、能发、能看图、能按名字找 |
| 存新文件到别处 | 不行 | 能，系统、隐藏、程序自己的文件夹除外 |
| 改已有文件 | 不行 | 不直接改，交给助手（越权操作要你批准） |
| 黑名单（密钥、记忆、登录信息、浏览器和密码管理器数据）、看起来像密钥的文件 | 不行 | 不行 |
| 屏幕和剪贴板 | 不行，提示词里也不出现 | 默认关；控制台打开后，你明确要求时能看。内容会发给模型服务，只留在这一轮，截图看完就删；密码管理器复制的内容不读 |

她写的标记：【画】【画动图】【翻记录】【看图】【存图】【发图】【做图册】【写文件】【发文件】【读文件】【看目录】【找文件】【群文件】，主人私聊还有【任务】【看屏幕】【读剪贴板】。群里的【找文件】只搜索当前聊天可读范围，【群文件】只查当前白名单群的云端文件；全机搜索仍只限主人私聊。

## 文件保存位置

每个聊天使用一个固定文件夹，收到的文件与生成的文件统一保存在这里，不再按日期分层：

- 群聊：`data/workspace/chats/group-群号/`
- 私聊：`data/workspace/chats/private-QQ号/`

【看目录：.】能看到该聊天所有日期的收件和产出；读写直接用文件名或相对路径。
写入重名文件会加序号保留新版本，不覆盖原文件。历史 `inbox/日期/聊天/` 路径继续可读、可发，
归并时保留旧文件和收件记录；其他群与其他私聊的权限边界保持独立。
关闭聊天文件夹功能时，收件备用位置是 `skills.files.inbox/聊天/`，同样不按日期分层。

读取时可用文件名自动定位子目录中的唯一同名文件；重名时先返回候选，不猜选。
本地找不到群文件时会尝试查询当前群文件列表并下载，群上传通知也会静默保存。
支持 `.xlsx` 工作表、单元格及公式缓存值读取；无缓存公式会注明未计算，不执行宏或外链。
已有文件会按当前请求列入可读目录，跨天仍可继续读取。详见 [群聊与文件修复记录](docs/usability-repair-20261112.md)。

历史收件可用 `uv run python scripts/migrate-chat-files.py` 预览，确认归属后加 `--apply` 执行。
脚本只复制、不删除旧文件，校验 SHA-256、保留修改时间，重名不覆盖，重复执行不会重复复制。
更早的无聊天编号文件按原始收件记录确定归属，无法确定的保留原状并报告；旧路径通过
`data/run/file_aliases.json` 指向归并后的文件，迁移回执保存在 `data/run/file-migrations/`。


## 后台任务与状态

技能调用不再设每轮次数上限；旧配置 `skills.max_rounds`、`skills.owner_max_rounds` 只兼容读取，
不再生效。文件权限、群文件夹大小、模型额度和任务运行时限仍按配置执行。

- 群里明确交代多步工作时，她可以用【任务：完整要求和文件路径】登记后台任务；也可直接发
  `/任务 完整要求和文件路径`，跳过模型判断。群后台使用独立模型连接执行现有权限受控技能，
  普通聊天结束后继续运行；不开放任意系统命令，不需要打开 `skills.group_agent.enabled`。
- 每个后台任务都有编号，状态与最近一步持久保存在 `data/run/tasks.json`；普通聊天的提示词
  会自动带上当前聊天的真实状态。群里查不到私聊或别的群的任务，主人私聊可查询全部。
- `/任务状态 [编号]` 查询状态，不填编号查当前聊天；`/停止任务 [编号]` 请求停止并保留产出；
  `/继续任务 编号` 从检查点及原任务线程继续。继续任务必须在原聊天发起，不把私聊结果发到群里。
  电脑助手与群沙箱任务仍只有主人能停止。
- 成功、失败或停止会回到原聊天通知；断线时通知会重试。程序重启会把活跃任务标成“已中断”，
  不会伪装仍在执行；可查询后用 `/继续任务` 恢复。运行时限由 `skills.background_timeout_minutes`
  配置（默认 30 分钟），与技能次数无关。
- 【转存文件：输入路径｜输出路径.md】把 PDF、Word 或文本的全部提取正文直接落盘，
  不经过模型逐字抄写，不受读文件的分段字数限制；保留现有读写权限，不覆盖重名文件。

## 读取 PDF

群聊和私聊收到的 PDF 都可以用【读文件：路径】读取。项目依赖 `pypdf[crypto]`，
`uv sync` 会安装 AES 加密支持；更新依赖或读取代码后，需要重启白璎主程序。
带加密标记但无需打开密码的 PDF 可以正常读；确实需要打开密码的文件会提示有密码。
扫描版与混合 PDF 现在支持按页视觉读取和全文识别。长文档仍按 `skills.files.read_chars` 分段读取。

- 【读页：路径｜2-4】查看原始页图，适合扫描文字、表格、图表和版式；默认一批最多 3 页，
  可通过 `skills.files.pdf_batch_pages` 调整（1～8 页）。【查文档：路径｜关键词】检索文字层及已识别的页，返回页码。
- 【转存文件：路径.pdf｜全文.md】保留页码提取正文；扫描页交给视觉模型识别，全文转存转入后台，
  支持查询、停止和继续；已识别页按 PDF 内容指纹缓存，继续时复用。疑难文字和图表数字须核对原页。
- 项目本地依赖增加 `pypdfium2`，锁定版本 5.15.2；`uv sync --locked` 安装到项目虚拟环境。
  PDF 文本、页图与逐页识别缓存位于 E 盘项目 `data/run/documents/`，每次读取仍重新校验源文件权限。

## Codex 工具与任务续跑

默认开启 `models.subscription.native_tools`：将已有 Python 技能作为结构化工具提供给 Codex，
参数与当前聊天权限仍由程序检查。普通聊天不开放系统命令；屏幕和剪贴板继续走临时会话。
旧版本接口不兼容时自动退回文本标记；DeepSeek 等兜底保留，并携带已执行的工具结果。

任务状态记录 thread/turn/item 的实际事件，能区分生成、执行工具、等待批准、压缩和中断；
模型一轮结束后还会核对任务结果，电脑助手另核对声明的产出文件，不直接当作任务完成。
受控后台技能任务的会话索引位于 `data/run/task-sessions.sqlite`，原生助手的线程号与策略指纹
保存在任务检查点。任务线程独立于聊天线程，日常睡眠整理和聊天轮换不会清空任务上下文。

- `/追加任务 编号｜新的要求`：在原聊天给运行中的任务追加要求；活动原生 turn 使用 steer，
  轮次之间保存后交给下一轮。电脑助手和群沙箱任务只有主人能追加。
- `/停止任务 编号`：向活动原生 turn 发 interrupt；后台技能和扫描识别在步骤边界退出，保留已有文件与缓存。
- `/压缩任务 编号`：对运行中的后台技能任务请求压缩，在当前轮结束后处理；原生电脑助手仍由 Codex 自动压缩。
- `/继续任务 编号`：用原线程及检查点恢复；重启后先明确显示已中断，不会自行假称仍在运行。
  旧记录缺少检查点、原生历史不存在或权限策略改变时，以现有要求和文件核对重建，并明确记录。

受控写文件保存内容指纹与目标路径，恢复时复用已核验产出，不重复生成同一文件。
任务通知和每个附件分别保存发送回执；断线未发送的可以重试，已经发起但未获确认的标为
“发送未获确认”，查询任务可取回文件，不盲目重发。原生命令中断后不能承诺从指令中间续跑，
恢复仍须核对已有文件，任意外部副作用也不能保证自动去重。

白璎子进程关闭 Codex 自带的记忆生成与记忆工具，继续以本项目的事件和长期记忆为准；
不改个人 Codex 全局配置。群原生命令沙箱开关继续默认关闭；启用时子进程使用系统 PowerShell，
避免选到沙箱不可读的应用捆绑副本，不扩大读取范围、不修改系统 PATH。

需要回退时，在控制台关闭“使用原生工具调用”和“PDF 按页读取和缓存”并重启，
或设置 `models.subscription.native_tools = false`、`skills.files.document_tools = false`。
现有记忆、每聊天文件夹、持久聊天与共享近期回忆继续保留。

## 配置

优先级从低到高：`config.toml`（进仓库）< `config.local.toml`（本机）< `.env`（本机）< 环境变量。API key 只能放 `.env` 或环境变量；复制 `.env.example` 为 `.env` 后填写。

本机 Ollama 等回环地址的模型连接自动直连，避免系统代理截断 `localhost` 请求；远端 API 仍使用原有代理和证书环境。该处理仅作用于应用 HTTP 客户端，不改系统网络配置。
